# system-adoption-playbook Reference

## When to Use
Use when rolling out a design system across multiple products or business units.

## Stakeholder Map
- Executive sponsor: funding and mandate
- Product leadership: roadmap alignment
- Design ops: standards and enablement
- Engineering platform: implementation support
- Accessibility lead: compliance evidence

## Adoption Maturity Levels
1. Aware: teams informed, no implementation.
2. Piloting: one product wave uses core components.
3. Scaling: multiple teams with shared KPIs.
4. Embedded: governance and release cadence institutionalized.

## Migration Sequencing
- Prioritize high-traffic products with moderate complexity.
- Use wave-based rollout by dependency and risk.
- Reserve a stabilization sprint after each wave.

## Onboarding and Enablement
- Onboarding checklist by role (designer, frontend, QA).
- Training calendar and office hours.
- Implementation support channel with SLA.

## Adoption Metrics
- Component adoption coverage
- Deprecated pattern burn-down
- Accessibility defect rate
- Time-to-ship for UI features
- Training completion and satisfaction

## Exception and Risk Handling
- Exception request requires expiry date and remediation owner.
- Risks tracked in weekly governance review.
- High-risk exceptions blocked from broad rollout.

## Feedback Loop and Dashboard Pattern
- Monthly adoption review with product leads.
- Dashboard sections: adoption %, defect trend, exception debt, migration velocity.
- Feed recurring issues back into governance and documentation updates.

## Failure Modes and Rejection Criteria
Reject rollout plans with no stakeholder owners, missing wave sequence, weak metrics, no enablement plan, or absent exception process.
